## 2. 证据来源（一手，非记忆推断）

1. **一手注册表** `mcp_web/packages/shared/src/lib/tool-category.ts`：`TOOLS_BY_CATEGORY`
   声明 185 工具 = company 16 + risk 38 + ipr 18 + operation 35 + history 34 + executive 44。
   本轮程序化 diff 结论：**91/91 短名与 `QCC_PHASE3_TOOL_NAMES` 逐一一致**。
2. **真实 ToolRuntime preflight**：`mcp_connector_tools_list(connectorId=qcc-company)`
   返回 6 个 server / 185 个工具，其中 risk=38、ipr=18、operation=35，与本契约一致。
3. **运行时名映射**：复用 `lib/qcc-phase2.js` 的 `qccToolRuntimeCandidates`（单一实现，覆盖六域），
   canonical `mcp__qcc-<domain>__<name>` → legacy `mcp__<domain>__<name>`。

## 3. 契约模块

- `lib/qcc-phase3.js`（新增，不改动已发布 0.4.0 的 `qcc-phase2.js`）：
  - `QCC_PHASE3_TOOL_NAMES`：三域精确短名清单（冻结）。
  - `QCC_PHASE3_DOMAIN_META`：三域 `access:'basic'` + `paid:true` + `requiresConfirmation:true`。
  - `QCC_PHASE3_REQUIRED_INPUTS` / `QCC_PHASE3_DEFAULT_REQUIRED_INPUTS`：必需输入契约。
  - `canonicalPhase3ToolName(domain, name)` / `QCC_PHASE3_ALL_CANONICAL_TOOLS` / `requiredInputsFor` / `isPhase3Tool`。
- `lib/qcc.js`：新增 `QccHostBridge.phase3Capabilities()` —— 只读 ToolRuntime 注册表，
  **不执行 QCC 工具、不产生付费调用**；返回按域 `registered/total/ready` + 域元信息。
- `lib/web.js`：新增 `GET /data-cleaning/api/phase3/capabilities`（与 phase2 同级，`paidCalls:false`）。

## 4. 输入 schema 契约

- 三域 91 个工具中，**90 个**仅需 `searchKey`（企业名称或统一社会信用代码）。
- **唯一例外** `get_judicial_document_detail`（risk · 裁判文书详情）额外要求 `documentId`（文书ID）。
- 其余输入均为可选项（分页游标 / 年份 / 角色 / 状态 / 日期 / 情感倾向等），
  不在必需契约内，避免固化上游易变的可选过滤参数。

## 5. 契约测试
