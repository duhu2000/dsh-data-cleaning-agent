# 企查查蓝 UI 对齐 · 本地开发与验收记录

日期：2026-09-06。开发基线：`main` / `0.8.7`；目标发布版本：`0.8.8`。本文记录发布前验收快照，实际发布结果以 Git Tag 和 npm Registry 为准。本轮不更新用户本机已安装的 DSH 插件。

## 共享规范与范围

唯一规范源：[DSH-UX-001 v1.1.0](../../../../AI-设计/DSH智能体开发交互规范方案.md)。采用本次补充的“首页 LOGO 与业务名称同排”规则。设计参考：[企查查蓝 Mockup](../../../../AI-设计/DSH智能体_企查查蓝_UI_Mockup_v1.1.0.html)。本文件只记录本插件的实现和例外，不复制共享规范。

| 页面 | 本轮实现 | 保留的边界 |
| --- | --- | --- |
| 左侧入口 / 首页 / 会话头 / 工作台 | 同一蓝色数据库 SVG；首页图标在名称左侧并垂直居中 | 普通会话与其他业务不注册此品牌单例；首页离开后恢复宿主图标、标题和预览标识 |
| 中央会话 | 简洁说明、下方独立五菜单、企查查蓝提示词触发器 | 原生输入、模型、权限、发送与已修复的图片识别链路不替换 |
| 提示词向导 | 居中弹窗、固定头尾、滚动正文、按维度勾选网格和字段搜索 | 搜索只过滤显示；128 个字段的含义、来源与已选状态不变 |
| 右侧工作台 | 当前任务/历史下划线标签、横向五步导航、字段网格及搜索、浅蓝表头 | 仍是唯一权威工作台；桌面停靠让位、移动全屏、关闭与展开逻辑不变 |
| 深色 / 窄屏 | 共享候选颜色、浅蓝主按钮配深色文字、可见键盘焦点、16px 移动输入 | 不在全局 `:root` 或 DSH 原生组件上覆盖品牌配色 |

字段搜索匹配维度中文名、工具名、字段中文名及内部字段 ID。全选/清空操作覆盖完整维度，不受搜索过滤影响，按钮提供说明。真实目录搜索“行业”显示国标行业、企查查行业、进出口行业种类；不可按原型的部分演示字段删减真实目录。

## 宿主兼容边界

只读检查本机 DSH `0.1.1-rc.2` 安装源码：品牌图形 `conversation.hero.brand.mark` 为 root/single 槽位。因此没有抢占该槽位，而是扩展现有会话级、可恢复的 Hero Bridge：在自有 `[data-phase="hero"]` 中定位宿主 headline 和 fishHitbox，插入自有 SVG，离开时还原。找不到已知结构时不改宿主图标。

这属于隔离的 DOM 兼容适配，不是跨版本稳定 API 承诺。`0.1.2-alpha.2` 和其他版本需重新做实际宿主 UI 验收，不沿用历史后端双基线结果作为本轮 UI 证据。

现有为兼容旧版访前尽调插件而可逆隐藏同会话已知 `.qccDock`/“尽调类型”节点的逻辑未在本轮扩展或移除；它仍是共享规范“各插件管理自己的业务区域”的历史例外，不能宣称所有插件组合均已无冲突。多智能体统一规范落地后应协调移除该兼容逻辑。

## 验证方式和证据

- `npm run check`：lint、文档版本、市场材料结构、npm 白名单检查和 **214 项测试通过**。
- `npm run test:ui`：真实 React + 隔离宿主 DOM + 本机无头 Chromium，浅色/深色各覆盖 1440×900、1024×768、390×700、900×500，共 **8 组通过**。
- 回归内容：首页图标同排/中心对齐、菜单位于原生输入框外下方、128 字段可见、字段勾选及搜索保持选择、主按钮颜色、向导正文滚动/固定底栏/Tab 循环/Escape、回填可编辑且发送按钮可用、工作台关闭展开不遮挡桌面输入框、离开业务后恢复宿主标志。
- 插件截图及机器结果位于 `_scratch/ui-layout/`（忽略的本地输出，不打包）；测试通过与否以最新 `results.json` 和进程退出码共同判断。
- 共享 Mockup 单独通过浅深色×四尺寸×三页面的 **24 场景**，包含同排 LOGO、向导/字段搜索、结果过滤下载及普通会话切换。该原型使用演示数据，不是插件真实业务验收。

运行浏览器回归需提供 `DCQ_UI_DEPS`（含 React、ReactDOM、esbuild）、`DCQ_PLAYWRIGHT` 和可选 `DCQ_CHROME`；详见 `scripts/ui-layout-regression.mjs` 文件头。

## 仍需实际安装验收

本轮未重装/重启用户正在使用的 DSH，未做新的真实 QCC 调用。发布与安装验收边界：

1. 用户已授权 `0.8.8` 本轮改动的 commit/push/tag/npm；发布前复跑门禁，完成后核对远端提交、Tag 与 Registry 版本。
2. 在目标 DSH 安装候选包，验证普通新会话 → 数据清洗入口 → 图片/Excel 提示词 → 回填发送 → 工作台核验 → 导出。
3. 切换访前尽调等已安装智能体，确认标题、图标、菜单及输入草稿互不抢占；检查宿主原生发送和暗色切换。
4. 若宿主 Hero 结构不匹配，先保留原生图标并记录兼容差异，不采用全局 CSS 或 root 品牌槽位绕过隔离。

回滚只需恢复上一已发布插件包；本轮不改变存储结构、Host 契约或任务制品，无数据迁移步骤。
