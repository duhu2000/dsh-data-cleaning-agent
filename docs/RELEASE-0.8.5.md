# v0.8.5：工作区关联与发送禁用修复

## 根因与范围

0.8.3 为避开空白会话复用，改为只传 cwd 创建清洗会话。DSH ConversationRoot 的
sessionWorkspace 通过 workspace.sessionIds 找到所属工作区；在 ready 状态下，无关联工作区的
空白首页 chipTitle 为空，inert 为 true。即使输入机已有任务说明，也会禁用发送/模型/权限控件。
0.8.4 的图片入口修复不改变此条件，因而两条图片入口仍无法发起会话。

0.8.5 恢复 workspaceId + 独立 sessionId 创建。没有模拟点击发送、强制移除 disabled、
伪造已发送消息、修改 DSH 安装包，也不绕过模型或 MCP 授权。

## 新会话隔离兼容边界

本机 DSH 侧栏及工作区浏览器均在点击时调用 ctx.workspaces.startSession。
原生实现复用 workspace 中的 blank session。插件生命周期内对此方法加可逆、窄范围适配：

- 仅当前清洗会话激活时，直接通过 sessions.create({workspaceId}) 创建普通会话再 open。
- 普通/其它会话调用原方法；不更改 connectWorkspace，不根据 DOM 文案判断导航。
- 并发点击合并；失败不清理原状态；其它导航或卸载后不打开迟到结果。
- 卸载时恢复原属性描述符；若被后续适配包裹，不覆盖别人，已销毁包装只转发。

startSession/create/open 为本机公开服务方法；方法装饰属于插件兼容层，不是 DSH 官方拦截API。
后续 DSH 升级必须重新验证侧栏调用路径和工作区表达式。

## 验证与升级

- 自动化测试从本机已安装的 DSH bundle 读取原生 inert 表达式；CI 使用经源码核对的同一表达式。
- 复现旧 cwd-only 首页禁用；关联工作区的新入口解除该项禁用条件。
- 覆盖创建失败、连续点击、普通入口转发、切换其它智能体、卸载恢复。
- 全量发布门禁使用 DSH_RELEASE_MODE=1 npm run check。

升级到 0.8.5 后重启 dsh web 并刷新页面，重新从“数据清洗补全”菜单进入。
旧 0.8.3/0.8.4 的无工作区会话不会被自动迁移、删除或发送；请在新会话重新选择图片和字段。
图片临时凭证有有效期，不应重用已过期凭证。真实浏览器发送和 QCC OCR 仍需安装后回归，
不得将本次契约回归描述为真实企业识别或真实模型发送已成功。
