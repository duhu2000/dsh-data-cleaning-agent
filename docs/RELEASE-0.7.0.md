# 0.7.0 · 一企一行 128 字段补全

> 版本：**0.7.0**
> 发布日期：2026-09-05
> 发布方式：推送 `v0.7.0` Tag 后，由 GitHub Actions 使用 npm OIDC Trusted Publishing 发布并创建 GitHub Release。

## 目标

0.7.0 把已经核对 QCC MCP 一手契约、能够稳定投影到单个 Excel 单元格的字段统一为 128 项目录：

- 基础 30 字段：企业工商信息 27、企业简介 3；
- 第一批 40 字段：联系方式 6、上市信息 15、税务开票信息 8、进出口信用 11；
- 第二批 58 字段：企业自身风险扫描 38、企业关联风险扫描 20。

字段 ID、中文表头、来源工具和发布批次由 `lib/qcc-field-catalog.js` 单一来源管理。一级行业、二级行业、
电话/邮箱/网址全集、风险明细、关联方名单等未被上游声明为稳定一对一值的数据不会进入主表。

## 业务与调用规则

- 提示词向导和规则确认页按 8 个来源工具展示字段，支持整组全选与清空。
- 同一工具选择多个字段时，每家企业只调用一次；调用上界按
  `唯一企业数 ×（主体定位 + 去重后的来源工具）` 计算，并在任何 QCC 调用前执行 300 次硬上限。
- 风险扫描明细由 Host 透视为稳定计数、命中摘要和关联方数量；数组不进入单元格。
- 新字段贯通任务草稿、Agent-owned 命令、候选续跑、结果预览及中文 CSV/XLSX；缺失值保留空列，
  股票代码、税号、电话和银行账号按文本保存。
- 生产风险目录变化记录为脱敏的 `QCC_RISK_CATALOG_DRIFT` 审计事件，不静默扩张稳定字段契约。

## 验收

- 字段目录：基础 30、第一批 40、第二批 58，共 128 个唯一字段 ID 和 128 个唯一中文表头。
- 自动化：`npm run check` 通过，186/186 测试通过；npm tarball 内容全部命中白名单。
- 真实环境：本机 DSH `0.1.1-rc.2`，两家企业选择第一、二批全部 98 字段及基础默认 5 字段。
- QCC 调用：8 个工具，估算 16 次、实际 16 次且全部成功；任务结果为补全 2、待核验 0、未匹配 0、失败 0。
- 结果 XLSX：`清洗补全结果!A1:DB3`，106 列、2 行；第一、二批中文表头完整，无重复、无内部英文表头、
  无公式错误，统一社会信用代码保持文本。

详细证据见 `docs/UI-WORKFLOW-V2-ACCEPTANCE.md` 第 9 节。

## 升级与回滚

- 升级：安装 `dsh-data-cleaning-agent@0.7.0`，完全停止并重新运行 `dsh web`。
- 回滚：重新安装 `dsh-data-cleaning-agent@0.6.3`，完全重启 DSH。
- 本版本不修改 `dc_workflows_v2` 持久化 schema，也不删除旧任务或耐久制品。
- 旧任务维持创建时的字段选择和既有制品；如需新增字段，升级后创建新任务并重新生成结果。
